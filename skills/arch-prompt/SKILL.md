# Architectural Prompt

把设计意图翻译成清晰、可检查、适配目标工具的图像指令。优先保持空间、构造和视角约束，而不是堆叠风格词。

## 工作流

1. 判断任务类型：文本生成、参考图生成、草图转效果图、局部编辑或变体探索。
2. 收集会显著改变结果的信息：项目类型、场地、设计概念、关键空间、材料、时间天气、视角、图像用途和目标工具。
3. 用户信息已足够时直接生成；只追问缺失且高影响的条件。
4. 按“主体与空间 -> 形体 -> 材料构造 -> 场地 -> 光照 -> 相机 -> 表现方式 -> 约束”组织提示词。
5. 根据目标工具追加必要参数，不把某个平台的语法混入其他平台。
6. 输出一个主版本和最多两个有明确差异的变体。
7. 检查提示词是否保留用户的功能、尺度、朝向和不可变元素。

## 按需读取

- 需要建筑词汇、相机、光照或表现方式时，读取 [references/prompt-library.md](references/prompt-library.md)。
- 用户指定图像工具或需要参数时，读取 [references/tool-adapters.md](references/tool-adapters.md)。工具版本变化快，只使用已确认仍受支持的参数。

## 提示词结构

```text
[项目与核心空间意图]
[体量、立面和构造逻辑]
[主要材料及其真实表面特征]
[场地、植被、人物和城市关系]
[时间、天气和光照]
[相机位置、镜头和构图]
[目标表现方式与细节等级]
[必须保留与必须避免的内容]
```

## 生成规则

- 使用可观察的设计特征，例如“连续水平檐口、深窗洞、粗糙清水混凝土”，不要只写抽象风格标签。
- 把最重要且不可变的元素放在前部，并在编辑任务中明确“仅修改什么、保持什么”。
- 写明视点高度、镜头方向和画面比例；避免同时要求互相冲突的相机视角。
- 对草图或模型截图，说明必须保留体量、开口、层数和透视关系。
- 不承诺图像可用于施工、法规审查或材料定样。
- 默认描述设计特征而不是模仿在世设计师；用户明确要求引用时，也要提供一个不依赖姓名的特征版。
- 不使用“最佳工具”“最新版本”等时效性结论，除非已经核验。

## 输出格式

```markdown
## 主提示词
[可直接使用的提示词]

## 避免项
[负面提示词或自然语言约束；目标工具不支持时说明]

## 参数
[只列目标工具确认支持的参数]

## 变体
1. [明确改变光照、材料或视角之一]
2. [另一种明确方向]

## 假设
- [未由用户确认但为了生成而采用的条件]
```

## 质量检查

- 项目类型、功能和场地关系没有被风格词覆盖。
- 材料描述包含尺度、接缝、反射或粗糙度等可见特征。
- 光源方向、时间和天气相互一致。
- 相机描述不冲突，画面用途匹配构图。
- 编辑任务列出了保持不变的元素。
- 平台参数属于用户指定工具，且没有未经核验的版本号。
