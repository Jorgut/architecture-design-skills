# Space Program

把任务区分为纯计算、经验估算或法规核验。先确认输入和口径，再计算；不要把经验值写成法定要求。

## 工作流

1. 识别用户要计算的指标、待求值和比较目标。
2. 收集会改变结果的必要输入：项目类型、地点、时间、面积口径、单位和适用标准。
3. 标记每项输入的依据：`用户数据`、`正式文件`、`明确假设` 或 `经验值`。
4. 统一单位并写出公式、代入过程和结果。
5. 区分计算结果与合规判断。缺少现行阈值时，输出“无法判断合规”。
6. 对区间输入给出区间结果；对假设做敏感性说明。
7. 用清晰表格汇总结果、依据、假设和待核验项。

## 信息优先级

按以下顺序采用数据：

1. 用户提供的项目批复、设计条件或现行规范条文
2. 当地政府或主管部门发布的现行文件
3. 项目任务书和经过确认的顾问数据
4. 有日期和适用范围的行业参考
5. 本技能中的非规范性经验值

来源冲突时采用更具体、更新且适用于项目所在地的来源，并明确说明冲突。不要静默选择。

## 按需读取

- 需要公式、单位口径或反推关系时，读取 [references/formulas.md](references/formulas.md)。
- 用户明确需要方案初估且没有正式标准时，读取 [references/benchmarks.md](references/benchmarks.md)。引用其中数值时必须标记为“经验值，待当地标准核验”。

## 计算规则

- 保留原始精度进行中间计算，最后一步再按用途取整。
- 面积、人数、户数和车位不得混用；写明每个率的分母。
- 户数、洁具、车位等离散数量通常向上取整，但先确认法规或任务书是否规定取整方式。
- 结果依赖假设时，至少给出基准值和一个合理上下界。
- 不凭城市名称套用日照、停车或消防系数；先取得项目适用文件。
- 不使用过期造价或售价数据给出确定投资结论。

## 输出格式

```markdown
## 结论
- [核心结果及单位]

## 计算
| 项目 | 数值 | 口径/来源 |
| --- | ---: | --- |
| 输入 | ... | 用户数据/文件/假设 |

公式：...
代入：...
结果：...

## 合规状态
- 已核验 / 无法判断 / 不适用
- 依据：文件名称、版本、条款或“未提供”

## 假设与待确认
- ...
```

## 质量检查

输出前确认：

- 单位和面积口径一致。
- 百分比、小数和千分比没有混淆。
- 所有经验值都已标记，且没有被表述为法规。
- 所有合规结论都能追溯到明确来源。
- 数量取整方向与依据已说明。
- 结果能够由展示的公式复算。
